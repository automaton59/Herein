# DSH live verification — 2026-10-23

本机 C → B → DSH 实跑证据。使用 B 的 independent bridge profile，不碰用户 desktop profile。

## 运行

```text
DSH bridge   http://127.0.0.1:8793
C Core       http://127.0.0.1:8794
bridge root  D:\Herein\tmp\live-c-b-20261023
keys         D:\Herein\tmp\live-c-b-keys-20261023
```

步骤：

1. `node adapters/dsh/scripts/cli.mjs keys --dir <keys>`
2. 启动 `cli.mjs serve --root <root> --install <DSH> --public-key ... --token-file ... --port 8793`
3. 签署 plan 安装 `adapters/dsh/fixtures/hello-v1`（disabled）。
4. 签署 plan `setBundle @herein/dsh-hello enabled:true`。
5. 启动 C Core：

```powershell
$env:HEREIN_CORE_HOST = '127.0.0.1'
$env:HEREIN_CORE_PORT = '8794'
$env:HEREIN_DATA_DIR = 'D:\Herein\tmp\live-c-b-20261023\core-data'
$env:HEREIN_DSH_URL = 'http://127.0.0.1:8793'
$env:HEREIN_DSH_TOKEN = '<transport token>'
node dist-electron/core/server.js
```

## 结果

C `GET /v1/agents`：

```text
provider: dsh / DeepSeek Harness / health ok
capability: herein_hello
lifecycle: external
actions: call
inputSchema: { type: object, properties: { name: string }, required: [name] }
```

C 调用：

```http
POST http://127.0.0.1:8794/v1/agents/dsh/herein_hello/invoke
{"action":"call","input":{"name":"hi"}}
```

返回：

```json
{
  "result": {
    "isError": false,
    "content": [{ "type": "text", "text": "hello hi (v1)" }],
    "value": "hello hi (v1)"
  }
}
```

DSH audit（`GET /v1/audit`）最后两条：

```text
sequence 15  capability.started   callId fc2b7d80-e773-4518-bc48-be3fad9ebc90
sequence 16  capability.finished  callId fc2b7d80-e773-4518-bc48-be3fad9ebc90  errorCode null
```

即：C 的调用真的穿过了 B 的 HTTP bridge，进入 DSH Tools registry 执行，并在 DSH 审计链留下一条 call 记录。

安装/enable 也有各自的 plan/approval/snapshot 记录，位于 bridge root 的 `state/`；transport token 和审批私钥不在仓库内。

## 边界

- 这是 B 的独立 profile（`herein-b-test`），不是用户正在使用的 DSH desktop profile。
- 安装 `hello-v1` 是为了验证能力桥；没有安装任何第三方不可信包。
- 该 bridge 进程与 C Core 目前仍在运行，便于继续检查；重启后 token/端口会变，C 需要重新配。
