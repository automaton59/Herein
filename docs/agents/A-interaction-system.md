# Agent A Brief — 全天候低延迟自主交流系统

> 给承接 A 工作流的 agent。本文只写背景、目标、边界、验收；不写实现方案。
> C（主系统）尚未启动。你先独立交付可运行、可演示的交互子系统，C 后续集成。

## 0. 一页结论

- **项目**：此间（Herein），本地优先的私人陪伴应用。
- **你的任务**：让蓝蓝在桌面上持续存在，能听、能说、能演，低延迟、可打断、全天候。
- **交付**：一套可独立运行的交互运行时 + 演示 + 指标 + 文档。
- **边界**：不碰 Core 数据/人格/记忆、桌面控制台、Android 聊天/状态、插件系统、白蓝设计；不决定“何时主动说话”（C 的主动性）。
- **核心难点**：低延迟语音闭环、正式 Live2D 身体、桌面常驻形态、8 小时稳定性。

## 1. 背景

此间现在是什么：

- Electron + React + TypeScript + SQLite；人格、关系、记忆、上下文装配、资产、备份已经落地。
- Core 常驻服务、Android Capacitor 客户端、B 站/网易云只读适配器、QQ Bot 骨架已经存在。
- 当前交互层仍是“打开窗口聊天”：桌面是聊天+设置；通话窗是 modal；语音是整段合成后播放；Live2D 是 Shizuku 技术验证；桌面没有常驻形象。

为什么需要 A：

- 产品方向变了：Android 承担主聊天，桌面承担“身体和声音”的陪伴。
- 用户不打开聊天窗，也应该能看见她、听见她、随时说话。
- 现在的零件（Live2DStage、CallWindow、手机朗读/口型、Core TTS 代理）是分开的，没有连成“一直在场”的系统。

当前硬缺口（背景事实，不是实现要求）：

- 语音约 4–5 秒/句，不能打断。
- Live2D 是 Cubism2 + Shizuku 验证模型；没有正式蓝鱼模型、没有 idle/视线，桌面没有口型。
- 桌面窗口是普通窗口；没有置顶/托盘/快捷键/多屏/休眠唤醒。
- 长时间运行、Android WebView 性能、音频设备切换都没有验证。

## 2. 目标

一句话：**让她在桌面上持续存在，能听、能说、能演，低延迟、可打断、全天候，不需要用户先打开聊天窗口。**

做到之后：

- 用户说话，她在接近真人的延迟内用语音回应，嘴和表情跟着动。
- 用户随时打断，她立刻停；停顿、思考、说话、idle 都是可感知的状态。
- 她有一个正式的蓝鱼形象，能待机、眨眼、呼吸、看人，被点、被拖有反应。
- 桌面有她的常驻位置：置顶、托盘、快捷键、开机自启、多屏、休眠唤醒都能用。
- 连续跑一整天不崩、不泄漏、不明显掉帧。

“自主”的边界：

- A 的“自主” = 常驻、免按钮、可打断、能维持在场感。
- **不包含**“决定何时主动找用户说话、说什么、对谁说”；这是 C 的主动性策略。
- A 可以上报 presence 信号（在桌前/空闲/正在说话/被打断），但发起与否由 C 决定。

## 3. 范围

- 实时语音闭环：听、说、打断、音频设备。
- Live2D 身体：正式模型、表情、动作、口型、idle。
- 桌面在场形态：常驻窗口、托盘、快捷键、多屏、电源状态。
- 本地性能与稳定性。

桌面是主战场。Android 可以复用同一套渲染/语音能力，但不是 A 的第一验收目标；Android 的性能降级由后续集成处理。

## 4. 非目标

- 主动性策略/时机/打扰预算。
- 人格、记忆、关系、受众隔离。
- 桌面控制台、Android 聊天/状态、插件系统、白蓝设计。
- 云 TTS、iOS、公开模型市场。
- 把模型、凭据、聊天数据提交进仓库或打包分发。

## 6. 约束

- 不碰 C 的领域：Core schema、记忆、人格、主动性、控制台、Android 聊天/状态、插件系统、白蓝设计。
- 不提交凭据、模型、聊天数据；`private/` 不进 git。
- 测试用临时端口/临时数据目录；不要破坏正在运行的服务。
- 正式模型可能受许可限制；只本地使用，不重新分发。
- 8GB VRAM 要和 Live2D/Electron 共处；性能要有降级路径。
- 不把“能跑 demo”当成“全天候可用”；要有长时间和真机证据。

## 7. 交付物

- 一套可独立运行的交互运行时/包。
- 一个能在用户机器上跑的演示：桌面常驻形象 + 语音回路 + 打断。
- 指标/测试：首包、RTF、首声、打断、fps、8 小时稳定性。
- 文档：如何运行、模型 manifest、已知限制、给 C 的集成说明。
- 一份短报告：做到了什么、没做到什么、证据。

## 8. 验收

目标级：

- 端到端首声进入 1.5–2.5 秒级；打断接近即时。
- 连续 10 句稳定；8 小时常驻不崩、不泄漏。
- 桌面流畅；Android 性能不够时能降级。
- 换正式模型只换 manifest，不改业务代码。
- 置顶、托盘、快捷键、多屏、休眠唤醒可用。

不要在没有证据时声称通过；用命令、指标、截图/录屏、日志说明。

## 9. 工作方式

1. 先读文档和代码，给出“现状理解 + 硬风险 + 验证顺序 + 交付边界”。
2. 不要先写代码；等确认后再开工。
3. 独立分支；不要直接改 `main`；不要提交 `private/`、模型、凭据。
4. 每步给证据；完成后更新文档。
5. 与 C 的集成放在最后；先保证独立可运行。
